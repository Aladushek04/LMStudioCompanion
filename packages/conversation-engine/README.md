## Текущее состояние

**CORE-1 принят; CORE-2 реализован для нативной проверки.** ID — `aladushek04/companion-core`, версия `0.1.1-core2`, revision 4. Собственный цикл сохраняет инструменты, разрешения, отмену и ошибки. CORE-2 добавляет сохранение новых общих фактов/заметок через текущую модель и владельца памяти панели. [CORE-1](../../docs/research/core-1-check.md), [CORE-2: проверки и ограничения](../../docs/research/core-2-check.md).

Это ещё не готовое объединение памяти, веба и документов. Пакет не включён в обычную сборку панели и не переключает обработчик автоматически. Одновременно с context-compressor или другим владельцем ответа его включать нельзя. Личные чаты при проверке не менялись.

Очередь разработки — [CORE-0–CORE-7](../../docs/plans/07-companion-core-stages.md), граница готового ядра — [требования](../../docs/requirements/companion-core.md). После проверки CORE-2 работа останавливается. CORE-3 автоматически не начинается. Разработка документов возобновится после полной приёмки Core и отдельного поручения.

## Проверка запоминания CORE-2

1. Перезапустите панель из обновлённых исходников: прежний процесс не знает новых операций канала. В разделе «Память» включите подключение к чату и скопируйте **путь** из поля «Файл подключения памяти». Сам файл с секретом открывать/пересылать не нужно.
2. В пустом тестовом чате включите только Companion Core как владельца ответа. companion-web, context-compressor и стороннюю память в этом чате выключите. В настройках Core заполните «Файл подключения памяти» и включите «Запоминание по просьбе». По умолчанию эта возможность выключена, другие чаты не переключаются.
3. `/core` должен показать `0.1.1-core2` и включённое запоминание. Напишите `Запомни, что проверочная метка — МАЯК-731.` Успешный результат содержит фактический текст, ID/редакцию и ID операции. В панели нажмите **«Обновить список»**, а не «Обновить предложения»: явная просьба пишет сразу.
4. Перезапустите панель и проверьте ту же запись в списке. Перепроверьте ссылку на предыдущую заметку, отрицание и цитату по [сценариям](../../docs/research/core-2-check.md). Карточки не используйте: это CORE-3.

Разбор и инструмент работают последовательно на уже выбранной модели. Обычный ответ при включённой памяти тоже проходит смысловую проверку до показа, поэтому появляется дополнительная задержка. Некорректный JSON/нехватка места/неоднозначность приводят к отказу или уточнению. Понимание языка и проверка текста зависят от LLM; автоматические тесты с поддельной моделью не доказывают качество текущей Gemma. Нативная приёмка CORE-2 ещё ожидается.

Сохраняется точный доступный текст одной заметки до 16 000 символов; без пересказа отсутствующего материала. Для разбора доступны до 12 последних подходящих сообщений и до 48 000 символов с пометкой пропусков; прикреплённые файлы не читаются. Подстановка сохранённого в последующие ответы относится к CORE-3.

Один владелец атомарно записывает факт и квитанцию; потеря ответа проверяется по ID операции без повторной записи. Неизвестный результат требует проверки панели. Перед первым расширением снимка владелец создаёт `before-core2-*.json` в своём каталоге. Старые снимки читаются; новый журнал не предназначен для открытия старым host 0.1.5. Возврат к прежнему плагину не требует отката обновлённого host. Журнал ограничен 2048 операциями: при заполнении явный отказ, без вытеснения квитанций. Старые предложения и ручные операции панели сохраняются.

Изменения относительно исходного снимка:

- собственные package/manifest и отдельные команды проверки/сборки;
- каталог кэша и извлечений вложений `.lm-companion-conversation` вместо `.lm-context-compressor`, без чтения и миграции чужого кэша;
- форматирование чисел в исходном английском `/usage` закреплено за `en-US`: исходные тесты смешивали фиксированные запятые и системную локаль; одно соответствующее ожидание теста также закреплено за `en-US`;
- выделен жизненный цикл `src/companion/turn.ts`, внутренние точки prepare/after, нативное подтверждение сторонних вызовов и диагностика `/core`; ошибки сессии не подменяются обычным ответом без инструментов;
- отмена прерывает ожидание повторного запроса; опубликованные вызовы не повторяются автоматически, другой источник модели не получается;
- свои настройки и статусы переведены на русский. Алгоритмы сжатия и исходные маркеры сохранены; часть отчётов сжатия пока английская. Прочие тесты upstream перенесены без правок;
- Node 24.22.2 и runner LM Studio Node 25.5.0 проверены отдельно: **387/387** тестов на каждом. Это не означает поддержку Node 25 у всей панели.
- CORE-2 добавляет проверку намерения/доступного текста, инструмент с ограниченными аргументами, квитанции единственного писателя и проверку неподтверждённых заявлений в обычном ответе. Zod включён в bundle с отдельной лицензией, см. THIRD-PARTY-NOTICES.md.

## Проверка без запуска модели

Из корня репозитория:

```powershell
node node_modules/typescript/bin/tsc -p packages/conversation-engine/tsconfig.json
node node_modules/vitest/vitest.mjs run --config packages/conversation-engine/vitest.config.mts --maxWorkers=1 --no-file-parallelism
node scripts/build-conversation-engine.mjs
```

Используйте проверенный Node 24 из Windows-комплекта для сборки; Node runner выбирает сама LM Studio. Последняя команда создаёт локальный кандидат в `.tools/companion-core` с lock-файлом, лицензией и `build-manifest.json` (SHA-256, версия, SDK, runtime сборки). Она не устанавливает и не включает его в LM Studio.

## Локальная установка и возврат

1. После проверок и сборки из `.tools/companion-core` выполните `lms dev --install --yes`. Команда устанавливает только собственный пакет с отдельным ID. При обновлении списка плагинов может понадобиться переиндексация средствами LM Studio/SDK.
2. В новом тестовом чате выключите context-compressor и другие владельцы ответа, затем включите Companion Core. Дополнительные tools provider можно выбирать отдельно. Запоминание настраивается по шагам выше; встроенный веб ещё отсутствует. companion-web в этом тестовом чате выключен.
3. Отправьте `/core`, затем обычный вопрос. `/usage` показывает расход контекста без генерации.
4. Для возврата сначала выключите Core, затем включите прежний context-compressor. Проверка такого возврата прошла в том же тестовом чате. Чужие плагины не удаляются и не перезаписываются.

Локальная установка не является релизом в Hub. Исходные SHA-256 в `UPSTREAM.json` описывают исходный снимок, а не текущие изменённые файлы. Подробности основы — в [исследовании](../../docs/research/context-compressor-foundation.md), текущий результат — в [отчёте CORE-1](../../docs/research/core-1-check.md).
