## Проверка без запуска модели

Из корня репозитория:

```powershell
node node_modules/typescript/bin/tsc -p packages/conversation-engine/tsconfig.json
node node_modules/vitest/vitest.mjs run --config packages/conversation-engine/vitest.config.mts --maxWorkers=1 --no-file-parallelism
node scripts/build-conversation-engine.mjs
```

Используйте проверенный Node 24 из Windows-комплекта для сборки; Node runner выбирает сама LM Studio. Последняя команда создаёт локальный кандидат в `.tools/companion-core` с lock-файлом, лицензией и `build-manifest.json` (SHA-256, версия, SDK, runtime сборки). Она не устанавливает и не включает его в LM Studio.

## Локальная установка и возврат

1. После проверок и сборки из `.tools/companion-core` выполните `lms dev --install --yes`. Команда устанавливает только собственный пакет с отдельным ID. При обновлении списка плагинов может понадобиться переиндексация средствами LM Studio/SDK.
2. В новом тестовом чате выключите context-compressor и другие владельцы ответа, затем включите Companion Core. Дополнительные tools provider можно выбирать отдельно. Встроенные память и веб пока отсутствуют; для этой проверки companion-web выключен.
3. Отправьте `/core`, затем обычный вопрос. `/usage` показывает расход контекста без генерации.
4. Для возврата сначала выключите Core, затем включите прежний context-compressor. Проверка такого возврата прошла в том же тестовом чате. Чужие плагины не удаляются и не перезаписываются.

Локальная установка не является релизом в Hub. Исходные SHA-256 в `UPSTREAM.json` описывают исходный снимок, а не текущие изменённые файлы.
