# Советник по настройкам LM Studio — 0.1.0

Обычное окно Windows для предварительного подбора контекста и GPU Offload. Достаточно установленной LM Studio с CLI и Windows PowerShell 5.1/.NET Framework (есть в актуальной Windows). Python, Node.js и Docker для советника не нужны.

## Запуск

В корне проекта откройте **Start-Advisor.cmd** двойным щелчком. Либо запустите `packages\advisor\Advisor.exe`. Файл exe запускает лежащие рядом исходники; переносить его отдельно от папки нельзя.

1. Дождитесь определения оборудования и моделей.
2. Выберите скачанную модель.
3. Нажмите **«Проверить настройки»**. Обычно проверка занимает несколько секунд или десятки секунд; неотвечающий CLI ограничен таймаутом каждого запроса.
4. Сравните строки таблицы. Выбранный вариант можно скопировать текстом, а весь отчёт — сохранить в JSON.

Советник использует только `ls --json`, `ps --json`, `load --help` и `load ... --estimate-only`. В этой версии нет кнопки применения настроек, замены модели или бенчмарка. API-сервер на порту 1234 не требуется; связь выполняется через CLI LM Studio. Для нормального результата запустите LM Studio и скачайте GGUF-модель.

## Что означают результаты

- **Есть запас сейчас** — оценка укладывается в текущую свободную память с запасом 2 ГиБ GPU и 4 ГиБ RAM. Успех реальной загрузки не гарантируется.
- **Нужно освободить память** — по общей ёмкости вариант подходит, но сейчас памяти мало. Уже запущенная модель тоже занимает GPU; советник не угадывает, сколько освободится после её выгрузки, и не выгружает её сам.
- **Мало запаса** — оценка не помещается с заданным резервом в бюджет GPU или RAM. Это не утверждение, что модель никогда нельзя запустить с другими настройками.
- **Оценка неполная** — не получены данные NVIDIA/RAM или CLI ответил в неизвестном формате. В таком случае пригодность профиля не объявляется подтверждённой.

Сначала проверяются 16К, 32К и 64К с полным GPU Offload, в пределах указанного моделью максимума. Если подходящего полного размещения не найдено, проверяются 75% и затем 50% GPU для 16К/32К. Первая приемлемая группа частичного размещения останавливает дальнейший перебор. Это ограниченный набор кандидатов, не поиск глобального оптимума.

Рекомендация предпочитает большую долю GPU, затем сбалансированные 32К; самое большое окно не считается самым быстрым. Процент GPU относится к выгружаемой части модели и не означает такой же процент расхода VRAM. Частичная выгрузка может заметно снизить скорость.

## Важные границы оценки

`Estimated GPU Memory` и `Estimated Total Memory` — значения CLI. ГиБ и десятичные ГБ переводятся отдельно. Total Memory консервативно сравнивается с RAM целиком: точный CPU-only расход из него не вычисляется вычитанием GPU. Это может дать более осторожную рекомендацию.

Для кандидатов явно заданы context, GPU и parallel=1, отключён engine-config-файл. Прочие параметры и особенности оценки определяет LM Studio. Оценка может отличаться от уже работающей модели с другими настройками KV-кэша, Flash Attention, batch и runtime. Если у вас сейчас работает 64К, красная строка для стандартной оценки не означает, что действующая конфигурация ошибочна.

Полная автоматическая классификация сейчас рассчитана на **одну NVIDIA GPU** с доступным `nvidia-smi`. Для AMD/Intel, нескольких GPU и неполной телеметрии программа показывает ограничения и не выдаёт ложный зелёный результат. Скорость не измеряется.

## Отчёты и отмена

Текущие отчёты остаются в `packages\advisor\data\runs`, отдельная папка на проверку. Они содержат названия моделей, ресурсы, оценки, аргументы команд и диагностический вывод; чатов, документов и токенов доступа в них нет. Отчёт сохраняется локально, наружу ничего не отправляется. Эти папки исключены из исходного комплекта.

**«Отмена»** прерывает собственную проверку; при закрытии окна собственный worker и его дочерние команды завершаются. Процессы LM Studio, загруженная модель и другие плагины не являются объектом остановки. Проверка CLI при необходимости может запустить штатный daemon LM Studio, но не загружает модель.

## Разработка и воспроизводимая сборка

Открыть окно напрямую:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Advisor.ps1
```

Проверки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Advisor.ps1 -SmokeTest
```

`Build.ps1` компилирует маленький C#-host с помощью установленной Windows PowerShell. Он использует .NET Framework и системную PowerShell assembly, не скачивает зависимости. Для пересборки сохраните прежний Advisor.exe отдельно: скрипт не перезаписывает существующий exe.

ExecutionPolicy Bypass действует только внутри собственного запуска программы, системная политика не меняется. Исходники `AdvisorHost.cs`, `Advisor.ps1`, `Advisor.Core.psm1` и `Advisor.Worker.ps1` лежат рядом с exe.
