# Диагностика общей основы — первый срез этапа 00

Запуск из корня проекта: **Diagnose-Companion.cmd**. Открывается консоль с кратким результатом; JSON-отчёт сохраняется в `data/diagnostics/capabilities.json`. Это отдельная диагностика; советник по памяти запускается прежним Start-Advisor.cmd.

Нужны зависимости из корневого `package.json` и собранная папка `dist`. В текущей рабочей папке они подготовлены. Скрипт сначала использует Node из установленной LM Studio, затем Node из PATH. На этой машине проверены Node 24.22.1 среды разработки и Node 25.5.0 из LM Studio; минимальная версия проекта — 22.21.1. Это комплект для разработки, упаковка для чистой машины остаётся задачей 3 плана 00.

## Что проверяется

- Один GET к `http://127.0.0.1:1234/api/v1/models`: доступность API и структура списка. Названия, идентификаторы и конфигурации моделей не сохраняются.
- Известные package.json, manifest, декларации SDK и точка регистрации установленного context-compressor. Его включённость в конкретном чате по этим файлам не определяется.
- Версия Windows-приложения из ресурсов указанного в installation metadata exe; этот exe не запускается. Из installation metadata используется только путь, аргументы запуска и рабочая папка игнорируются.
- Консервативный выбор режима по доказательствам. `tools-only` означает отсутствие нового управления генерацией; он сам не устанавливает и не включает инструменты в чате.

Состояние **«не проверено»** сохраняется для совместимости обработчиков, постоянного ID чата, устойчивых библиотек FileHandle, управления Thinking и остальных возможностей, которым нужен отдельный интеграционный тест. Найденный метод SDK не получает статус работающей функции.

## Ограничения и ошибки

Диагностика не запускает API-сервер и daemon, не делает генерацию, не загружает/выгружает модели, не регистрирует плагины и не меняет MCP или базу памяти. Учётные данные не читаются: при 401/403 проверка объясняет ограничение. Поддерживаются только loopback-адреса без учётных данных и параметров URL; перенаправления не выполняются.

GET ограничен 5 секундами и 1 МиБ ответа. Чтение версии через PowerShell отдельно ограничено 2,5 секунды. Отмена — Ctrl+C. Итог записывается через отдельный временный файл; при отмене до начала атомарного переименования (rename) предыдущий отчёт сохраняется. Начавшаяся фиксация завершается, и успешный результат уже содержит новый отчёт, даже если Ctrl+C поступил во время этой короткой операции.

## Разработка

После установки Node с npm, из корня проекта:

```powershell
npm ci --ignore-scripts
npm test
npm run typecheck
npm run build
npm run diagnose
```

Если npm отсутствует, но зависимости уже установлены:

```powershell
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.build.json
node dist/host/src/diagnose.js --url http://127.0.0.1:1234
```

Параметры: `--url <локальный адрес>`, `--output <путь JSON>`, `--timeout-ms <1..30000>`, `--help`. Успешный запуск возвращает код 0, недоступный API/ошибка — 1, отмена — 130. Тесты используют временные локальные HTTP-серверы и не требуют рабочей модели. В среде с запретом loopback-соединений им нужен доступ к локальной сети.
