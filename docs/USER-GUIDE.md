# LM Studio Companion: запуск и текущее состояние

## Открыть панель

В папке проекта дважды нажмите **Start-Companion.cmd**. Откроется браузер с локальной панелью. Консоль запуска оставьте открытой; для остановки нажмите в ней **Ctrl+C**. Закрытие одной вкладки браузера не останавливает локальный сервис.

Панель работает на этом компьютере по адресу 127.0.0.1:17837. Адрес без ссылки запуска не даёт доступ к диагностике: у каждого запуска собственный ключ сеанса. Он передаётся браузеру без записи в журналы, удаляется из адресной строки и сохраняется только в хранилище вкладки. После перезапуска сервиса старый ключ недействителен — откройте панель через ярлык заново. Если вкладка с ключом потеряна, сначала остановите прежнюю консоль через Ctrl+C, затем запустите ярлык: повторный запуск при уже работающем сервисе блокируется.

## Первая установка и обновление

Для Windows x64 используйте готовый архив `LMStudioCompanion-0.1.2-win-x64.zip`: распакуйте его и откройте **Install-Companion.cmd**. Установщик покажет папку и список изменений; Enter подтверждает установку, N отменяет. По умолчанию используется `%LOCALAPPDATA%\Programs\LMStudioCompanion`. После завершения окно остаётся открытым с путём установки. Затем откройте **Start-Companion.cmd в папке установки**. Node 24.22.2 уже включён с лицензией; npm, Docker и установленная LM Studio для открытия самой панели не нужны. Без API панель объяснит отсутствие подключения.

Можно работать переносно: вместо установки открыть Start-Companion.cmd прямо из распакованного архива. Его данные останутся рядом в `data`; версионный откат доступен только после установки. Для новой копии **исходников из GitHub** сначала откройте Install-Companion.cmd: он один раз подготовит проверенные Node/npm, зависимости и сборку. Для этого требуется интернет и Windows tar. Затем используйте Start-Companion.cmd. Повторный запуск панели не запускает установку.

Для обновления остановите панель через Ctrl+C, распакуйте новый комплект и запустите его Install-Companion.cmd в ту же папку назначения. Версии сохраняются отдельно в `versions`; данные лежат вне них. Чужая непустая папка и изменённые вручную ярлыки не перезаписываются: выберите другую папку либо сохраните свою правку и восстановите исходный файл. Конфигурация MCP, плагины LM Studio и выбор обработчика не меняются.

Для другой папки и предварительного просмотра можно вызвать `scripts/Install.ps1 -Target 'D:\Программы\Companion' -Preview`; для применения — тот же путь с `-Apply`.

## Откат и удаление

Остановите панель и откройте **Rollback-Companion.cmd** в установленной папке. Он возвращает предыдущую активную версию и её ярлыки. Откат самой первой установки отключает приложение. Настройки, память и документы не удаляются. Устаревшая резервная копия не может затереть более новое обновление.

**Uninstall-Companion.cmd** удаляет только неизменённые файлы собственного комплекта. Перед этим закройте панель и советник. Занятый файл прерывает подготовку удаления с восстановлением перемещённых файлов; после закрытия приложения можно повторить. Данные `data`, копии `backups`, изменённые и посторонние файлы, запись установки и небольшие служебные манифесты сохраняются. При переносном запуске версионного удаления нет: данные находятся в распакованной папке.

## Что уже работает

- Обзор подключения к локальному API LM Studio на порту 1234. Проверка запускается при открытии; её можно повторить или отменить.
- Версия приложения, время последней проверки, подробности подтверждённых и непроверенных возможностей.
- Переходы к разделам модели, ответов, памяти и документов с объяснением их доступности.
- Существующий автономный советник: **Start-Advisor.cmd**. Его оценки не применяют настройки и не измеряют скорость.
- Отдельная консольная диагностика с JSON-отчётом: **Diagnose-Companion.cmd**.

Окно Diagnose остаётся открытым и после успешной проверки: прочитайте результат и нажмите любую клавишу для закрытия. «Не проверено» в возможностях означает отсутствие подтверждённой интеграции, а не поломку самой диагностики.

Companion сейчас не владеет генерацией. Общение и существующие инструменты остаются в LM Studio. С версии 0.1.2 включено ручное управление собственными записями памяти. Применение профилей, переключение Thinking и управление документами ещё не включены. Панель показывает это прямо; кнопок, обещающих неподдержанную операцию, нет.

## Управление памятью — C2

Откройте раздел **«Память»**. Он работает и без подключённой LM Studio. Кнопка **«Добавить запись»** открывает форму: введите текст, категорию, выберите общую память или проект и при необходимости закрепите запись. Технические ID вводить не нужно. Поиск и фильтры помогают найти запись; **«Изменить»** сохраняет ручную правку, **«Забыть»** сначала просит подтверждение. Escape или «Отмена» оставляют запись на месте.

Пока это собственный список Companion: в чат записи ещё не подставляются (это C3). Записи старого persistent-memory автоматически не читаются и не переносятся (перенос относится к C5). Проект пока является ручной областью записи, а временная память недоступна до привязки чата.

При правке в двух окнах устаревшая версия не перезаписывает новую. Черновик остаётся в форме. **«Разрешить конфликт»** покажет актуальный сохранённый текст; подтвердите замену своим черновиком или отмените действие. Если другой редактор снова изменит запись, операция опять остановится. Для конфликта удаления обновите список и подтвердите удаление заново. При ошибке диска черновик тоже остаётся; при потере связи сначала обновите список — запрос мог успеть сохраниться до разрыва соединения.

Переход в другой раздел сохраняет черновик в текущей вкладке. Закрытие или перезагрузка вкладки не является сохранением записи. **«Экспортировать память»** скачивает snapshot постоянных записей JSON; он может содержать личные сведения. Восстановление и импорт этого файла пока не выведены в интерфейс.

Данные собственного списка находятся в `data/host/memory` внутри рабочей/установленной копии. Локальный владелец один; сетевые пути не поддерживаются. Старый архив 0.1.1 не содержит этот экран — используйте исходники с новой сборкой или комплект **0.1.2**. Перед обновлением остановите прежнюю консоль через Ctrl+C; не заменяйте и не удаляйте папку `data` вручную. Удаление записи не стирает прежний текст из старых чатов и ранее экспортированных копий.

## Если подключение не найдено

Откройте LM Studio, запустите её локальный API-сервер на порту 1234 и нажмите **«Проверить подключение»**. Панель сама не включает сервер и не загружает модель. Если API требует авторизацию, текущая проверка не читает ваши токены; это ограничение будет видно в подробностях.

Отмена сохраняет предыдущий успешный результат с прежним временем проверки. При недоступном сервере выводится новое состояние отсутствия подключения. Ошибка доступа к самой панели объясняется отдельно: запустите её через ярлык, чтобы получить актуальный ключ сеанса.

## Где хранятся собственные данные

- `data/host/settings.json` — предпочтения Companion. Сейчас они не применяются к LM Studio; будущие элементы управления в интерфейсе недоступны. Повреждённый файл не заменяется молча значениями по умолчанию.
- `data/host/.host-lock` — служебная запись владельца. В Windows единственного владельца дополнительно защищает именованный канал, который ОС освобождает даже при аварийном закрытии. При нормальной остановке запись удаляется.
- `data/diagnostics` — отчёт отдельной консольной проверки; `data/ui` — снимки проверок интерфейса в среде разработки.

Эти папки исключены из Git. Исходные чаты, memory.db и пользовательские документы панель не читает. Отмена сохранения собственных предпочтений действует до начала атомарной фиксации файла; уже начатое переименование завершается.

В версии 0.1.1 на Windows после аварийной остановки достаточно повторить запуск: оставшаяся служебная запись восстанавливается после получения исключительного владения у ОС. Одного PID для этого недостаточно. Старый PID-файл 0.1.0 заменяется только при отсутствии прежнего процесса; если он ещё существует, запуск блокируется консервативно. Работающий экземпляр не вытесняется: используйте его браузер или остановите прежнюю консоль через Ctrl+C. Не удаляйте lock-файл у работающей программы вручную. При повреждённой записи сначала убедитесь, что все прежние процессы Companion завершены, и только затем удаляйте `data/host/.host-lock`; настройки и остальные данные оставьте на месте.

Аналогично, после аварийного завершения установщика удалять `.install-lock` в корне установленного приложения можно только после проверки, что установка, откат и удаление завершились. При обычной ошибке блокировка снимается автоматически. После сбоя питания между заменой ярлыков и фиксацией указателя восстановление может потребовать повторной установки из исходного комплекта; это не откат данных.

## Индикатор в чате

Своей полосы контекста у Companion пока нет: в выбранном безопасном режиме не подтверждён доступ к циклу компрессора. Состояние Companion видно в локальной панели. У самого context-compressor в проверенной версии есть настройки **Prompt meter → Off** и **Announce compaction in chat**. Companion не меняет их автоматически. Собственные статусы инструментов и переключатель появятся после отдельной проверки; нулевой расход токенов пока не измерен. Подробности: [исследование](research/chat-visualization.md).

## Разработка и проверки

```powershell
npm test
npm run typecheck
npm run build
npm run test:panel
npm run package
npm run test:release
```

Последняя команда открывает отдельный headless Edge с временным профилем. Она проверяет интерфейс на тестовых данных, включая отсутствие подключения, отмену, клавиатуру, ширину 320 px и масштаб текста 200%. Рабочая модель не вызывается. Если Edge установлен в другом месте, задайте `COMPANION_BROWSER` с путём к его exe.
