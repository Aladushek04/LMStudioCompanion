## Уточнения плана

- Ruling: автоматический переход к vision пока выключен — доступ к свободному vision-slot/безопасность вложенного вызова при Parallel=1 не подтверждены. Цена: плохое извлечение явно остаётся partial/empty; пользователь может отдельно попросить визуальный просмотр.
- Ruling: до подтверждения tools session/владельца вывода нативная автоматика не регистрируется. Библиотеки планирования, бюджета, источников и ограниченного исправления проверяются через явный адаптер. Цена: действующий чат ещё не получает гарантированное автоматическое чтение.

## Задачи 2–3: библиотеки политики и контроля

Готовы planWebAction, WebTurn/runWebPlan, SourceRegistry, decideWebAnswer, TurnRepair/repairToolArguments и canRetry. До реализации новые TS-тесты падали из-за отсутствующих модулей. Проверены обычная просьба прочитать URL, поиск актуального, явная картинка, выключенный интернет, URL в коде/цитатах, дедупликация, общий лимит страниц и исправлений одного хода, отмена и deadline даже при зависшем адаптере. WebTurn требует verified toolsSession от явно переданного адаптера; без него выполняется 0 вызовов и возвращается UNSUPPORTED. Это библиотека будущей интеграции, не доказательство наличия настоящего tools session.

Реестр выдаёт ID сам, изолирован одним ходом и сохраняет независимую копию источника. Проверка ID не проверяет смысл утверждений. Ответ source-unavailable детерминирован для недоступного запрошенного URL; успешная другая страница его не заменяет. Redirect принимается только по привязке реестра; позднее неудачное чтение не подменяется прежним успехом. Канонические SourceRecord/TurnContext/TurnBudget не переизобретались.

Исправление JSON независимо написано для одного однозначного случая — завершающей запятой вне строки, затем обязательно schema validation. Дубли ключей и неоднозначный JSON отклоняются, URL и имена инструментов не додумываются. TurnRepair ограничен 0/1 попыткой и принадлежит WebTurn. canRetry разрешает только перечисленные read-инструменты и запрещает повтор Remember/Forget/неизвестных writes при любом результате. Сам helper вызовы не перезапускает.

## Остальные уточнения и границы

- Ruling: не копировать код компрессора под Community License без отдельной проверки условий и не импортировать его из установленной папки. Изучен существующий invalidToolRequestResult (toolWrap.ts:63–65, handler.ts:2135–2143): он предлагает модели исправить вызов, а не детерминированно чинит JSON с общим лимитом. Собственная узкая политика написана независимо. Цена: её подключение к действующему обработчику ещё впереди; прежний компрессор не менялся.
- Ruling: до проверки реального токенизатора ограничение библиотеки — 24 000 символов источников, а не обещанный лимит токенов. Цена: перед включением автоподстановки нужен расчёт реального окна и резерва ответа. Режимы off/auto/research существуют в планировщике, но видимые переключатели и источники в панели не включаются без настоящего канала данных.
