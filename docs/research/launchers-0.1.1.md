# Исправление запуска Windows — 0.1.1

Дата: 2026-10-29. Запрос пользователя: панель не запускается после закрытия, Diagnose появляется и исчезает, Rollback/Uninstall из распакованного комплекта выводят стек отсутствующего install-state.json.

## Причины и исправления

- В рабочей и указанной переносной папках действительно оставались PID-файлы завершённых процессов. Сервис проверял только наличие .host-lock через open(wx), поэтому аварийное закрытие блокировало следующий запуск. В Windows теперь используется исключительное владение именованным каналом на основе канонического пути данных. Канал не принимает команды и не передаёт данные/токены; ОС освобождает его вместе с процессом. Метаданные снимаются до освобождения канала. Новая запись после аварии заменяется только после получения исключительного владения. Старый PID-формат дополнительно требует отсутствия процесса; живой или недоступный legacy PID не вытесняется. Ссылки вместо метаданных отклоняются.
- Установщик, откат и удаление используют тот же механизм для папки данных под своей install-блокировкой. Существующий host не вытесняется, а мёртвые метаданные больше не блокируют обновление. Одного PID или отсутствия файла недостаточно для определения свободной папки.
- Диагностика в указанной копии работала и возвращала exit 0. Именно при успехе CMD не делал pause. Общий генератор теперь сохраняет код возврата и оставляет результат Diagnose на экране; проверены exit 0 и exit 7. Корневой Diagnose использует тот же PowerShell-вход, включая подготовленный runtime. Окно успешной установки тоже остаётся открытым с путём установленной версии.
- Распаковка архива не создаёт установленную версию и историю отката. При отсутствии install-state.json Rollback/Uninstall теперь объясняют переносной режим и указывают, какой ярлык использовать после установки. Ничего не удаляют и не печатают ожидаемый Get-Content stack trace. Настоящие операции установленной версии сохранены.

Unix-ветка остаётся консервативной с wx-файлом; автоматическое восстановление в этом исправлении проверено только на Windows. Если метаданные повреждены либо старый PID уже занят другим процессом, автоматическое вытеснение не выполняется.

## Проверки

- До исправления воспроизведены RED для старого lock, переносного отката/удаления, обновления с мёртвыми метаданными и жёсткой ссылки вместо служебной записи.
- **92/92 Vitest**, 11 файлов, typecheck прошёл. Включены реальный дочерний Node с аварийным завершением, запрет второго владельца даже после удаления metadata-файла, сохранение возможного legacy-владельца, запрет подмены через hardlink, обновление после stale lock и сохранение settings.
- **check-launchers.mjs — PASS**: PowerShell 5.1 и настоящие CMD с синтетической диагностикой, pause и сохранение exit code; переносные сообщения без stderr.
- Собран `releases/LMStudioCompanion-0.1.1-win-x64.zip`, 33 файла payload + манифест, закреплённый Node 24.22.2 и лицензии. **check-release.mjs — PASS**, 11 составных сценариев, дополненных проверками переносных ярлыков, повторного запуска и обновления после force-stop без ручного удаления .host-lock.
- Независимый reviewer не нашёл подтверждённых P0–P3. Его ограничения Windows sandbox (loopback/hardlink/rename) не выдаются за провал продукта; полный основной прогон выполнен с необходимыми правами в изолированных папках.

## Применение к указанной папке

Папка `releases/LMStudioCompanion-0.1.0-win-x64` обновлена на месте до payload 0.1.1; название папки сохранено. До замены проверены контрольные суммы всех 33 прежних файлов. Заменены только принадлежащие манифесту неизменённые файлы, включая 10 записей с новым манифестом. Создана резервная копия заменяемого кода в `backups/launcher-fix-*`. После замены все хеши совпали с новым манифестом. Папки data/backups пользователя не переносились и не очищались; свои метаданные владельца восстановлены безопасным механизмом.

На этой самой папке выполнены два настоящих запуска с HTTP 200, включая перезапуск после принудительного закрытия. Её Diagnose проверен через CMD: exit 0, полный отчёт и предложение нажать клавишу. Браузерные окна для теста не открывались. Выполнена только read-only диагностика; генерация, изменение модели, MCP-конфига, сторонних плагинов и memory.db не выполнялись.

Старые манифесты этапа 00 и исходного веба остаются историческими снимками и не переписываются.
