# D3: подбор фрагментов, источники и бюджет

Дата: 2026-10-30. [План](../plans/04-documents-d3.md), [машинный отчёт](../../reference/documents-d3-check.json). Это проверка подбора в панели и библиотека для будущего D4; действующий чат не изменён. Публичный ZIP v0.1.5 прежний.

## Контракт

Схемы scope/request/result заданы в packages/documents/src/retrieval-types.ts. Scope содержит ID элемента D2 (отдельно от adapter ID), ревизию, source SHA, text version и явный список разделов. null означает весь текст, [] — пустую область. Неизвестный раздел, stale hash/version/revision или изменённый текст дают ошибку, без расширения поиска.

Разделы определяются по Markdown #–###### и строкам «Глава/Раздел N…» (арабские/латинские римские номера). Заголовок до200 символов, до100 на файл; слишком длинная строка не распознаётся заголовком, превышение количества даёт явный отказ поиска. Строки внутри fenced-блоков кода с backtick/tilde не считаются заголовками. Родитель включает дочерние разделы; пересекающиеся диапазоны объединяются. Это границы **извлечённого текста**, не подтверждённые физические страницы PDF. Нераспознанный заголовок не получает выдуманного ID.

Фрагменты не пересекаются, до1200 UTF-16 позиций, с границами по заголовкам/пробелам. ID учитывает document ID, text version и точный диапазон. Для области и поискового индекса используется единый сканер заголовков: из индекса удаляются только подтверждённые строки; комментарии кода и нераспознанные длинные строки остаются данными. Оригинальный текст цитат не изменяется. Ранжируется тело, а не имя файла/заголовок: Unicode-слова, простая нормализация русских окончаний, TF-IDF cosine и положительное совпадение слов. Универсальный score0.5 не используется. Запрос всей области включает также несовпавшие фрагменты в пределах тех же ограничений; иначе выбираются совпадения внутри явной области.

До5 готовых снимков по250000 символов; до2500 фрагментов, измеряются первые24 кандидата, включается максимум12. Отдельно считаются пропуски budget/limit, найденные/included IDs, диапазоны и частичный охват. «Нет совпадений», «нашлось, но не поместилось», пустая область и ошибка различаются. Запрос всего документа при неполноте предлагает разбор по частям.

## Бюджет и источники

Токенизатор измеряет полный сериализованный блок с реальными source/chunk IDs, рамкой и окончательными счётчиками охвата; после пропусков размер проверяется ещё раз. Резерв ответа max(2048, ceil(contextLength×0.15)), tools1024 — как в B/C. Нет оценки символы/4 или подмены недоступного tokenizer фиктивным успехом. Возвращается именно измеренный payload.

SourceRecord сохраняет общий формат. Атомарный SourceRegistry.registerSources публикует только финальные уже измеренные записи, без регенерации ID и частично добавленного пакета. Chunk каждого опубликованного источника соответствует included-набору/диапазону/версии. Наличие ID не подтверждает правильность ответа на вопрос. Документ — недоверенные данные, не инструкция.

Панель использует listLoaded() и instance-bound LLM; не вызывает model()/load()/prediction/embedding. Сейчас требуется один уже загруженный экземпляр. Измеряется его prompt template с вопросом и блоком на **пустой истории**, не полный действующий чат; D4 обязан передать собственный measure реальной истории. Выбор модели из нескольких в этом экране не реализован. SDK1.5.0 остаётся прежним.

## API и жизненный цикл

POST /api/documents/:id/search — строгий JSON до64KiB; GET :id/searches/:searchId/sources/:sourceId/chunks/:chunkId — точный опубликованный фрагмент. Прежние Host/Origin/token-проверки. Запрос обязан соответствовать текущим выбранным ready-элементам владельца D2. Fence проверяет принадлежность набора/ревизии/выбор после await; отменённый/старый результат не сохраняется.

Один tokenizer-запрос панели, deadline8с. Отмена запускает закрытие выделенного SDK-клиента, raw preparation/measure и teardown удерживают слот до settlement. Ошибка teardown блокирует следующий запрос до перезапуска; ошибка/timeout не маскируется no-match. Принудительная остановка работы серверного backend не гарантируется. Закрытие host отменяет запрос и инициирует teardown, не ожидая бесконечно некооперативный tokenizer.

Один результат хранится внутри RAM-набора D2, с тем же TTL. Новый поиск/изменение материалов инвалидируют прежние источники; ссылка после deselect/remove/смены версии/запроса недоступна. UI сбрасывает результат/диалог при изменении снимка, отменяет старые запросы, сохраняет вопрос/явные разделы/требование полного охвата при переключении галочки файла. Оригиналы и плагины не редактируются.

## Качество и проверки

Размеченная synthetic fixture tests/fixtures/documents/retrieval.json: **10/10 ответимых** вопросов имеют опорный фрагмент среди включённых (recall@12); **4/5 неответимых** дают no-match. Известный false retrieval: «Кто заместитель координатора?» находит сведения о самом координаторе без ответа про заместителя. Это измеренное ограничение лексического baseline; наличие источника не является проверкой ответимости. В D4–D5 этот случай нужен для проверки честного «нет данных» при непустом, но неответном источнике. Embeddings не загружались; универсальное семантическое качество не обещается.

- Unit/API: scope/версии/ревизии, одинаковые имена и title-only trap, вложенные/дублированные/неизвестные заголовки, пустой выбор, schema included↔SourceRecord, частичный/полный охват, бюджет/рамка/reserve, NaN/negative/fractional count, отмена/fence, атомарный registry, авторизация, exact citation, deselect invalidation, raw cancellation/deadline и безопасные ошибки.
- Edge synthetic: реальный host, вопрос/разделы/exact fragment, no-match/budget/error/cancel, смена выбора при задержанном ответе, сохранение ручной области и полного охвата, HTML escaping, 320px/200%/клавиатура, pageerror0. Проверены D2/overview/memory регрессии; screenshots desktop/mobile просмотрены.
- Native scripts/check-documents-search.mjs: фиксированные TXT/PDF D0 и текст evaluation fixture; уже загруженная google/gemma-4-12b-qat, без embeddings. Три found-результата с exact citation; токены590/590/565 независимо пересчитаны тем же instance-bound tokenizer/template, равны отчёту и <=26176 с резервом. В разделе «Управление» запрос бюджета даёт no-match. Прежний source после изменения выбора недоступен; исходные SHA/loaded set прежние. Генерация, model loading, чат и 26B не вызывались.

Итоговая проверка после паузы выполнена автором без субагентов, в соответствии с прямым ограничением пользователя. Прежнее прерванное ревью не возобновлялось; завершённого независимого ревью нет. Проверка автора слабее независимой; merge в main не выполняется.

Найдены и исправлены одним RED→GREEN проходом два Important/P2: ложные разделы внутри fenced code, обрывавшие выбранную главу; потеря поискового содержимого длинных строк, которые не распознаны заголовками. Общий сканер и отдельный searchText сохраняют область и исходную цитату, включая блок кода через границу фрагментов. После исправлений: **243/243 теста в39 файлах**, typecheck/build и Edge D3/D2/overview/memory — pass. Первый полный прогон одновременно с Edge имел один timeout5000ms существующего memory CRUD-теста; изолированный набор памяти18/18 и повторный полный последовательный прогон243/243 прошли без изменений этого теста. Нативная проверка, описанная выше, выполнена до паузы; после исправления заголовков без изменения SDK/tokenizer повторно не запускалась.

Отложен Minor: SourceRecord.status пока консервативно partial даже при включении всего короткого текста. Точные included-диапазоны и охват уже есть в coverage; уточнение этого статуса остаётся для политики ответа D4. Неполное чтение за полное не выдаётся.

D3 завершён в описанном объёме. D4 (действующий чат/режимы) и D5 (приёмка/релиз) остаются следующими поручениями. Папки/постоянный индекс — G, OCR вне первого выпуска.
