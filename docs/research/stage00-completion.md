# Завершение этапа 00

Завершена [задача 3 и основа этапа 00](../plans/00-foundation.md) в режиме tools-only, на основе [DESIGN](../DESIGN.md). Ветка feat/foundation-panel сохраняется. Дата проверки: 2026-10-29. Собственное управление генерацией не включено.

## Решения реализации

- Выпуск Windows x64: заранее собранные host и React-панель, автономный Node LTS 24.22.2 с официальной SHA-256 и лицензиями. npm конечному пользователю архива не требуется. Исходники отдельно подготавливаются одной кнопкой Install-Companion.cmd.
- Установка в отдельную папку: неизменяемые versions/<id>, атомарный указатель активной версии и резервная копия предыдущего состояния. Собственные данные лежат вне versions и сохраняются при обновлении, откате и удалении. Операции изменения защищены отдельным lock; активную панель перед ними нужно остановить.
- План MCP из исходной задачи уточнён для реально существующего продукта: у панели нет собственного stdio MCP-процесса. Фальшивая MCP-запись не создаётся, пользовательский mcp.json не читается и не меняется. planInstall сохраняет переданную тестовую конфигурацию целиком; регистрация будущих инструментов потребует отдельного descriptor и проверки.
- Откат меняет только наше состояние и bootstrap-файлы. Изменённые пользователем файлы не перезаписываются молча. Удаление работает только по собственным манифестам и сохраняет data/backups; постороннюю папку установщик не принимает за свою.
- Для индикации исследуются реальные публичные контроллеры SDK. ToolCallContext.status по декларации не виден модели; PromptPreprocessorController имеет createStatus, но не createContentBlock. Это не подтверждает глобальную полосу контекста в tools-only. Второй владелец генерации не добавляется. Если runtime-путь не подтверждён, предусмотренный ТЗ запасной вариант — локальная панель, настройка в чате недоступна/выключена, а не фиктивно работающий индикатор.

Для частичного отката, junction и удаления после EPERM сначала воспроизведены падающие регрессионные тесты, затем GREEN. При удалении файлы сначала перемещаются в собственную staging-папку; ошибка до фиксации возвращает их на место. Успешная фиксация отключает приложение; PowerShell удаляет только неизменённые файлы из receipt после выхода Node. Безопасное удаление и повтор после EPERM проверены fixtures, реальный цикл — готовым комплектом. Дополнительно RED→GREEN проверен повтор первой установки после частичного сбоя: пустая проверенная папка получает собственную неактивную запись до копирования, поэтому её не принимают за чужую при повторе.

В первом smoke обнаружены зависимости от автозагрузки модуля архивов/Get-FileHash PowerShell; заменены прямыми .NET API для ZIP и финального удаления. На чистой исходной копии выявлены ANSI-пути Windows tar и запрет npm на один config-файл для user/global; исправлены относительными ASCII-аргументами и разными пустыми конфигами. Полные сценарии после исправлений прошли.

Данные реальной памяти/чатов не читались, чужие MCP-настройки не открывались; используется только синтетическая конфигурация. Не выполнялись загрузка/переключение модели, генерация, патч установленных плагинов или публикация Hub. Тестовый процесс панели остановлен только в собственной временной папке; его оставшаяся блокировка снята после завершения собственного дерева процессов. Это не тест graceful-остановки консольным Ctrl+C; штатное закрытие host проверяется API-тестами.

## Принятые уточнения плана

- Ruling: merge MCP не применяется — у локальной панели нет MCP-сервера. Конфиг сохраняется без изменений; цена решения — будущему инструментальному серверу потребуется отдельная регистрация и проверка отката.
- Ruling: отсутствие Docker не блокирует основу — панель от него не зависит. Проверка Docker веба относится к 06; цена — веб-комплект ещё не проверен этим установщиком и не включён в ZIP.
- Ruling: исследование чат-индикации закрыто предусмотренным ТЗ запасным вариантом локальной панели. Метрики чужого prediction loop недоступны; цена — собственной полосы и переключателя в чате пока нет, стоимость unknown. [Основания и передача этапу B](chat-visualization.md).

Известная граница установщика: атомарен файл указателя версии, но не весь набор файлов при отключении питания между заменой bootstrap и указателя. Обработанные ошибки копирования восстанавливаются; после аварийного завершения ОС может потребоваться восстановление исходных ярлыков из выбранной папки versions и повтор установки. Данные вне versions не откатываются и не удаляются. Манифесты проверяют целостность, ZIP не имеет цифровой подписи издателя.
