# C2: ручное управление памятью

Дата: 2026-10-30. Выполнен только C2 из [подэтапов C](../plans/03-memory-stages.md). Версия комплекта — **0.1.2**. Подстановка памяти в чат (C3), предложения из чата (C4) и перенос прежней базы (C5) не включались.

## Что доступно

Раздел «Память» показывает собственные записи Companion и позволяет добавить текст, категорию, общую/проектную область и закрепление, найти запись, отфильтровать проект, исправить, забыть с подтверждением и скачать JSON snapshot постоянных записей. Технические ID и revisions не нужно вводить вручную. Session-область пока не предлагается без подтверждённой привязки чата. Категория и источник не выдаются за доказательство истинности факта.

Хранилище C1 открывается лениво при первом запросе памяти в фиксированном подкаталоге `settingsDir/memory`; путь из HTTP не принимается. Один процесс host владеет хранилищем. Shutdown ждёт принятые записи и затем освобождает оба владельца. Если память занята или недоступна, status/остальная панель продолжают работать и можно повторить загрузку.

API защищён прежними проверками Host/Origin/token и лимитом JSON 64 KiB. Клиент не выбирает source, identityKey, manualPriority и произвольные поля. Ревизия обязательна для правки/удаления; stale write даёт 409, отказ записи — 500, недоступный владелец — 503. Поиск и фильтры локальные; их значения и факты не добавляются в URL/журналы. Текст отображается обычным React-текстом, без HTML-интерпретации.

Редактор сохраняет черновик при отказе записи и смене раздела. При конфликте «Разрешить конфликт» показывает актуальный текст и предлагает явно подтвердить замену своим черновиком. Revision берётся только из этой подтверждённой версии; промежуточное изменение снова приводит к конфликту. Для устаревшего удаления нужно обновить список и подтвердить его заново. Сетевой сбой не объявляется ни подтверждённым сохранением, ни подтверждённым откатом: пользователь должен обновить список перед повтором.

[Машинный итог проверки](../../reference/memory-c2-check.json).

Первый API-набор дал RED (404), затем GREEN. Браузерный сценарий сначала не нашёл кнопку добавления и затем прошёл. Независимое ревью нашло один P2: после 409 черновик оставался с прежней revision и не имел нормального пути сохранения. RED → GREEN добавлено явное разрешение с показом актуального текста и повторной проверкой revision. Отдельный RED → GREEN уточнил восстановление после stale delete, где редактор не открыт. Других подтверждённых замечаний ревью нет.

## Поставка и границы

Архив: `releases/LMStudioCompanion-0.1.2-win-x64.zip`, комплектный Node 24.22.2, 33 файла payload. SHA-256: `420206c52c848c595d4458dd121b1e803567a9d26c3f3d154a3fb68e645df746`. Старые архивы/папки 0.1.0/0.1.1 не объявляются обновлёнными и не заменялись. Для источников достаточно новой сборки; для установки/переносного запуска использовать 0.1.2 и [инструкцию](../USER-GUIDE.md).

Панель работает без LM Studio, но ещё не сообщает модели новые факты. Общая/проектная область здесь — ручная организация списка, а не автоматическая изоляция чатов. Экспорт не равен импорту/восстановлению: эти кнопки пока не включены. Удаление не стирает прежние значения из старых чатов и ранее сделанных копий. В списке показываются первые 50 совпадений с «Показать ещё»; поиск охватывает весь загруженный список.

Настройки модели, действующий владелец генерации, память стороннего плагина и инструменты LM Studio не переключались. C2 завершён; следующий отдельный подэтап — C3.
