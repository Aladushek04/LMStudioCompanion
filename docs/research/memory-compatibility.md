# C0: исходные условия памяти

Дата: 2026-10-30. Выполнена проверка исходников и метаданных установленного `khtsly/persistent-memory` и существующей основы Companion. Личная memory.db, записи, переписки и пользовательские настройки не читались. Код продукта и действующие плагины не изменены.

## Наблюдения

- package.json установленного плагина: `lms-plugin-persistent-memory` 1.0.1, SDK `^1.5.0`, sql.js `^1.14.1`, декларируется MIT. Отдельного LICENSE в корне установленного пакета нет. Лицензии зависимостей не подтверждают условия самого плагина; его код не копируется до отдельной проверки upstream.
- `src/index.ts` регистрирует настройки, toolsProvider и promptPreprocessor. В просмотренных исходниках не найден публичный management-сервер для безопасного управления всей памятью из панели. Наличие внутренних методов БД таким API не является.
- `src/storage/db.ts`: sql.js держит БД в памяти, `persist()` экспортирует её целиком и выполняет writeFileSync. Исключения подавляются. Это не подходит как готовая реализация надёжного сохранения и не допускает записи панели в тот же файл вторым процессом.
- Схема/типы содержат id, content, category, tags, confidence, source, scope, project, created/updated/last-accessed timestamps, accessCount и supersedes. При будущем импорте нельзя ограничиться упрощённым контрактом плана и потерять остальные поля. Проверено по CREATE TABLE и типам, а не чтением пользовательской БД.
- В Companion уже есть ChatScopeStore с запретом смены проекта привязанного чата и RAM-sessionId. Это библиотека; подтверждённого постоянного ID действующего чата для автоматической project/session-подстановки пока нет. Угадывать его по глобальной настройке нельзя.

## Решение для C1

Разрабатывать собственный независимый владелец хранилища в отдельном data-dir, на синтетических записях. Совместимость означает сохранение смысла, областей и полей при подготовленном импорте; она не требует импортировать подавляющий ошибки код старого плагина. Старое хранилище продолжает принадлежать прежнему плагину до отдельного переноса C5.

Перед реализацией C1 дополнить контракт записи: revision для обнаружения устаревшей правки, признак закрепления предпочтений, устойчивое отношение старого/нового варианта и защита приоритета ручной правки. Исходный упрощённый MemoryRecord не содержит всего необходимого. Проверки приоритета входят сразу в хранилище, а не откладываются до подключения AI.

Автоматический доступ к project/session в чате остаётся закрытым до отдельного доказательства идентификации чата. На этой границе возможен первый рабочий recall только общей памяти; этот предел нельзя выдавать за завершённую поддержку всех областей.

## Что выполнено и что ещё не проверялось

C0 завершён как исследование и разбивка работ. Хранилище C1 ещё не реализовано; crash-safety, импорт, миграция личных данных и фактическая память в чате не проверялись и не объявляются работающими. Проверены UTF-8 и относительные ссылки новых документов; тяжёлые тесты модели для документирования не запускались.
