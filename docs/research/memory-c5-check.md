# C5: перенос прежней памяти и итоговая приёмка

Дата: 2026-10-30. Панель **0.1.5**, исходники C5 **ae9032f**. Собственный companion-web revision 3 не менялся. Пользователь сообщил: **старых записей нет, достаточно готового переноса**. Личная миграция не выполнялась, старые БД и переписки не читались.

## Что работает

На экране «Память» появился перенос выбранных постоянных записей из отдельно подготовленной offline-копии. Остановка прежнего владельца и выбор именно копии подтверждаются пользователем. Приложение не ищет и не открывает исходную БД по пути. Просмотр в RAM ничего не пишет; применение требует выбора записей и отдельного подтверждения с отменой по умолчанию.

Принимаются SQLite user_version=2 с обычной таблицей memories и явно помеченный JSON Companion persistent-memory-v2. JSON — обменный формат для этого переноса, а не заявленный экспорт стороннего плагина и не собственный snapshot из кнопки экспорта. SQLite читается из загруженных байтов в :memory:, без второго файлового писателя. Проверяются версия, таблица, скрытые столбцы, области, поля, количество строк и размер. Views/virtual/generated columns не выполняются как источники памяти.

SQLite deserialize доступен с Node 24.16; C5 проверяет capability перед чтением. В комплекте Node 24.22.2; на старом runtime SQLite-перенос отклоняется как неподдерживаемая копия, поэтому для него нужен комплектный Node. Модуль node:sqlite имеет статус release candidate; зависимость ограничена переносом offline-копии, обычное хранение C1 остаётся snapshot. [Первичная документация Node SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).

Стабильные ID импорта вычисляются из прежних ID. Повтор, ручная правка и tombstone не допускают дубль или восстановление забытого факта. Разные ID не объединяются по смыслу: пользователь проверяет выбор. Поля, даты, счётчики, связи и неизвестные данные сохраняются в metadata как исходный JSON; SQL int64 вне безопасного диапазона сохраняется строковым sqliteInteger, BLOB — sqliteBlobBase64. Неизвестная область и project без проекта отклоняются. Session исключается, не превращаясь в постоянные данные.

Единственный владелец C1 сначала проверяет весь пакет и записывает проверенный before-import-UUID.json, затем атомарно применяет пакет. Повтор успешного подтверждения идемпотентен. Устаревшая revision, два окна, отмена до commit, ошибка диска и повреждённая резервная копия не дают ложного успеха. Откат после restart доступен только до следующего постоянного изменения; текущая RAM-session остаётся. Цена этого решения — более поздний откат требует отдельного согласования записей, а не восстановления поверх ручных правок.

Корневой формат snapshot v1 не менялся: служебный маркер хранится в metadata импортированных записей. Revision остаётся монотонной после отката и повторного импорта; старое разрешение на recall или редактирование не становится действительным снова. Содержимое прежних чатов и summaries не переписывается.

## Проверки

- **170/170 тестов, 30 файлов**, typecheck и build прошли. Новые тесты: parser 5, owner 8, API 3. Проверены реальный SQLite в RAM, неизвестные поля и большие числа, связи, session, повтор/правка/delete/restart, backup/rollback, отказ между backup и commit, отмена, устаревшая revision, совместимость v1 и повторное появление ID после отката.
- Проверен пакет из 1700 выбранных UUID: JSON больше 64 KiB принимается только bounded apply endpoint до 512 KiB. Другие JSON endpoints сохраняют лимит 64 KiB. Загрузка offline-копии ограничена 8 MiB / 10 000 строк; previews — два на 10 минут, квитанции — 16 на 10 минут.
- Настоящий Edge headless: выбор offline-копии, подтверждение, просмотр без записи, выбор, отмена по Escape, ошибка ENOSPC с сохранением выбора, повтор, успешный импорт, откат, повреждённый файл, ширина 320 px, шрифт 200%, клавиатура, отсутствие pageerror. Скрипт: scripts/check-memory-migration.mjs. Старые сценарии memory-panel, proposals и overview также прошли.
- Одно независимое итоговое ревью: четыре замечания исправлены через RED → GREEN — размножение общего JSON-конверта, лимит массового подтверждения, SQL int64 и сохранение собственного __proto__ в исходных данных. Отложенных minor нет.

## Минимальная проверка с текущей 12B

Использована уже загруженная google/gemma-4-12b-qat через SDK и действующий препроцессор, с настоящим tokenizer, отдельным синтетическим владельцем и пустой историей. **Это не повтор нативного UI-теста с компрессором.** Совместимость нативного чата подтверждена C3/C4; C5 не меняет hooks, сторонние плагины или настройки чата.

Импортированы global и project, одна session пропущена. В новую подстановку попал только global; модель вернула вымышленный код **ЛАЗУРЬ-615**. После отката активных записей и refs стало ноль, следующий ответ — **4**. Артефакт проверки data/memory-c5-live.json содержит только результат синтетического теста и исключён из Git; воспроизведение — scripts/check-memory-migration-live.mjs с явным ID уже загруженной 12B. Личная история, дополнительная модель, 26B, повтор тяжёлого сжатия и изменение настройки загрузки не использовались.
