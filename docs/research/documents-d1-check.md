# D1: надёжное чтение TXT и текстового PDF

Дата: 2026-10-30. D1 — библиотечный адаптер, **без экрана документов и подключения к чату**. D2–D5 остаются следующими подэтапами. [План](../plans/04-documents-d1.md), [основания D0](documents-api-report.md), [машинный отчёт](../../reference/documents-d1-check.json).

## Контракт и владение входом

createDocumentAdapter(backend, limits?) предоставляет prepareDocuments(inputs, ctx, options?): Promise<OperationResult<DocumentState[]>>. Это собственный контракт Companion, не одноимённый API LM Studio. Общие OperationResult и TurnContext не дублируются.

Вход — строгий объект {name, bytes: Uint8Array} для каждого явно выбранного файла. Пути, дополнительные поля и произвольные сохранённые SDK-handles не принимаются. До API проверяются реальные размеры typed-array views через intrinsic getters, затем копируется их фактическое содержимое без пользовательского итератора и повторно проверяются размеры снимков. Изменение исходного Buffer после вызова не подменяет читаемый текст; переопределённые byteLength/Symbol.iterator не обходят caps. Файлы не ищутся на диске и не читаются из путей, предложенных моделью. Для нативных вложений D4 ещё должен доказать безопасное получение именно выбранных bytes; готового такого подключения в D1 нет.

Каждый документ получает свои id, operationId, turnId и SHA-256 исходного снимка. Одинаковые имена не объединяют содержимое. textHash и content version учитывают нормализованный текст, source hash, parser identity и версию нормализатора. SDK identifier/bytes/локальный путь не возвращаются в DocumentState. Адаптер не сохраняет пользовательский текст на диск и не добавляет его в память.

## Состояния и ограничения

| Ситуация | Результат |
|---|---|
| Принятый снимок обрабатывается | processing; без выдуманного процента прогресса |
| Валидный непустой текст | ready, текст/хеши/версия и полный text-range locator |
| Пустой файл, скан, неверный UTF-8/NUL, неподдержанный формат или плохая PDF-сигнатура | unreadable и конкретная причина; текст не объявляется готовым |
| Ошибка SDK, непроверенный parser, неверный результат/извлечённый объём | error, без SDK stack, путей или ложной причины |
| Выбор уже не актуален по проверке владельца | stale; поздний текст не публикуется |
| Отмена/таймаут набора | OperationResult с CANCELLED/TIMEOUT; незавершённые состояния получают ошибку, позднего ready нет |
| Уже идёт работа этого экземпляра | BUSY; новый набор не ставится в неограниченную очередь |

ready означает **готовый текст**, не готовый поиск: retrieval всегда отдельно not-prepared. Непустой PDF не считается полностью семантически понятым; таблицы, изображения и OCR не реализованы. Locator содержит начало/конец в UTF-16 offsets нормализованного текста и имя; физических страниц не выдумывает.

Пределы первого адаптера: **5 файлов, 8 MiB каждый, 20 MiB суммарно, 250 000 UTF-16 code units извлечённого текста на файл; 30 секунд на файл и 90 секунд на набор**. Factory overrides могут только уменьшать эти пределы. Проверены как превышения, так и точные байтовые границы с изолированным тестовым backend; настоящий native backend проверялся на небольших fixtures, не на всех больших PDF. Ограничение входных bytes не доказывает жёсткого ограничения памяти native parser.

TXT допускает UTF-8 с BOM/без; invalid UTF-8 и NUL отклоняются до upload. BOM и CRLF/CR нормализуются, существенные начальные/конечные пробелы сохраняются. Текст сверх лимита не обрезается молча. Содержимое, похожее на инструкции, остаётся данными; LLM/tools не вызываются. Это не обещание защиты поведения будущей модели от всех prompt-injection — интеграция ответа относится к D4.

Для корректно принятого набора отдельный непрочитанный файл не стирает результаты других: ok=true может содержать ready и error/unreadable, с предупреждением. Потребитель обязан проверять state каждого документа, а не считать ok=true доказательством чтения всех файлов. Ошибки входного набора, отмена, timeout и stale дают ok=false.

## SDK backend и отмена

createSdkDocumentBackend использует только files.prepareFileBase64, getDocumentParsingLibrary и parseDocument. Проверяются настоящий FileHandle текущего files namespace, name/size/type и явно разрешённый builtIn version 1. Неизвестный parser не запускается, другой backend или embedding не загружается. Ошибка неподдерживаемого шифрования PDF не объявляется недоступностью всего API.

В SDK 1.5 upload и parser-identification RPC не принимают signal. Поэтому backend сохраняет их исходный Promise до завершения и проверяет abort перед следующим RPC. Внешний adapter прекращает ожидание, но остаётся BUSY, пока его исходный backend Promise не завершится. Это сериализация вызовов данного экземпляра, не доказательство остановки работы сервера. Native parse получает signal; прекращение CPU-работы сервера этим не доказано.

Сроки дополнительно проверяются монотонными часами после await, между SDK RPC, после подготовки хешей и перед публикацией ready. Если event loop был заблокирован и callback таймера опоздал, просроченный результат отклоняется; следующий файл/RPC не стартует. Эта проверка не прерывает синхронный код посреди выполнения.

Владелец обработки обязан использовать **отдельный SDK client** и закрывать его после задачи/при восстановлении. Backend сам не закрывает переданный клиент, чтобы не оборвать чужие операции. D2 должен владеть одной активной обработкой и её teardown; создание нового adapter на каждый запрос ради обхода BUSY недопустимо. Temporary handles не используются как постоянная библиотека.

isCurrent — синхронная проверка владельцем актуальности выбора перед публикацией. Требуется явное true; ошибка/false/Promise не разрешают чтение. Для немедленной остановки при смене выбора владелец также abort-ит сигнал. onState получает копию с operationId; её изменение не меняет внутренние данные. Уведомления не ожидаются и не подменяют результат парсера. Поздняя асинхронная ошибка onState после возврата метода не может попасть в уже возвращённый warnings; отдельная доставка таких ошибок пока отложена. Потребитель должен использовать итоговый результат чтения, а не считать callback подтверждением сохранения/публикации текста.

## Проверки

- Unit: собственная идентичность/хеши/locators; одинаковые имена; BOM/CRLF/UTF-8/NUL; caps и превышение текста; malformed/защищённый PDF; плохой результат; отмена/поздний ready; file/batch deadlines; owner fence; BUSY после некооперативного backend; копии callback state; fake/foreign/несовпавший handle; неизвестный parser; отсутствующий API; безопасные ошибки и отсутствие model/embedding обращений.
- Реальный адаптер: LM Studio **0.4.27**, SDK **1.5.0**, parser **builtIn/1**. UTF-8 TXT — ready, 132 символа после нормализации; текстовый PDF — ready, 159 символов, оба контрольных фрагмента найдены; scan — unreadable/NO_TEXT; malformed и AES-256 PDF без переданного пароля — error/PARSER_ERROR. Пять исходных снимков и loaded set до/после совпали. Генерация, загрузка embedding/моделей и изменение чатов не выполнялись.
- Защищённая fixture создана pypdf из синтетического PDF D0, с явно публичным тестовым паролем d1-public-fixture. После тестового decrypt независимо найдены оба маркера; две страницы отрисованы и просмотрены. Native parser пароль не получал. Это проверка отказа, не реализация открытия документов по паролю.
- scripts/check-documents-adapter.mjs не принимает пользовательские пути и использует безопасный текущий outcome отчёта D0. Результат без полного текста — ignored data/documents-d1-live.json, копия фактов — reference/documents-d1-check.json.

Команды: Vitest tests/documents; полный Vitest с --maxWorkers=1 --no-file-parallelism в разрешённом loopback-окружении; tsc --noEmit; scripts/build.mjs; scripts/check-documents-adapter.mjs. **212/212 тестов в 34 файлах, typecheck/build прошли.** Одно независимое ревью: два Important исправлены одним проходом RED → GREEN (7 новых регрессионных случаев: итератор/реальные размеры, задержанные file/batch таймеры, поздний upload без последующих SDK RPC). Повторного ревью не было; корректность исправлений проверена тестами и полным green suite. Reviewer проверял код/offline tests, независимый live/visual тест им не выполнялся; live и просмотр fixtures выполнял автор. Отложен один Minor — доставка поздних асинхронных ошибок onState; это не меняет текст или статус парсера.

D1 не включает HTTP-route, выбор файлов в панели, retrieval, источники ответа, строгий режим или нативный чат. Существующие плагины/компрессор не менялись, новая модель не запускалась. Публичный ZIP/tag 0.1.5 остаётся прежним: новый релиз — после полной приёмки D.
