# Индикация в чате: решение этапа 00

Дата: 2026-10-29. Исследована установленная LM Studio 0.4.26, SDK 1.5.0 и context-compressor 0.8.3, revision 27. Только исходники и типы; личные настройки и история не читались, установленный плагин не изменялся.

| Канал | Что подтверждено исходником | Ограничение |
|---|---|---|
| ProcessingController.createStatus/createContentBlock | Компрессор использует их в собственном обработчике; у блоков указан includeInContext:false | Нужен доступ к его циклу. Создание второго обработчика ради полосы запрещено |
| PromptPreprocessorController | Omit исключает createContentBlock и setSenderName, оставляет createStatus | Это обработка ввода; непрерывного наблюдения за чужой генерацией не даёт |
| ToolCallContext.status/warn | SDK прямо описывает статусы как невидимые модели; доступны signal/callId | Кандидат для будущих собственных нативных инструментов, не доступ к чужому циклу или метрикам MCP |
| ToolsProviderController | Наследует BaseController | Произвольная чат-панель не объявлена |

Основания: локальный SDK `index.d.ts`: 7210, 9583–9606, 9698; полный путь и хеш — в [capability-report](capability-report.md). У компрессора `src/config.ts:206–232` уже есть `showStats` (Announce compaction in chat, default true) и `meterDisplay` (status/sender/off, default status). `src/handler.ts:1528–1552` отображает итог сжатия и счётчик. Это его собственные настройки; Companion их не читает и не меняет. Исходники стороннего плагина в поставку не входят.

**Решение:** этап 00 завершается с предусмотренным [ТЗ](../requirements/chat-visualization.md) запасным вариантом: состояние Companion показывается в локальной панели. Дополнительная полоса в чате не регистрируется; неподтверждённого процента и фиктивного переключателя нет. Существующий компрессор продолжает отображать свой индикатор.

Сравнение фактических входов и токенов вкл/выкл, tool-turn, сжатия, отмены и ошибок **не выполнено**, стоимость остаётся unknown. Декларация SDK и includeInContext:false не выдаются за измеренные 0 токенов. Дополнительных генераций ради оформления нет.

При реализации собственных инструментов этапа B проверить ToolCallContext.status на синтетическом сценарии и только затем добавить сохраняемый переключатель собственного адаптера. До подтверждения нулевой стоимости он выключен по умолчанию. Требования и будущий checklist остаются в ТЗ, а не считаются уже пройденными.
