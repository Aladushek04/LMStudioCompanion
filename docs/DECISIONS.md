# Решения и обязательные проверки

## Решения пользователя от 2026-10-29

Это требования к будущей реализации; их фиксация не означает готовность функций.

- При нехватке контекста сначала сохранять материалы текущего запроса: явно выбранные документы, изображения и URL. Затем важные закреплённые предпочтения; затем дополнительные результаты поиска и обычные записи памяти. Старую переписку при необходимости сокращать с сохранением совместимости с context-compressor. Место под ответ резервируется до добавления материалов.
- Для большого документа поддержать два сценария: автоматический подбор фрагментов по вопросу и явное указание пользователем файлов, глав, страниц или разделов. Явное указание задаёт область поиска и имеет приоритет над автоматическим выбором. При частичном изучении сообщать об объёме и пропусках; просьбу проверить весь документ не выдавать за выполненную после чтения отдельных фрагментов.
- Ручные исправления памяти имеют приоритет. Старая формулировка из переписки или фонового извлечения не должна автоматически возвращать прежнее значение. Новое противоречащее сведение предлагается на подтверждение пользователя.
- Добавить визуализацию состояния прямо в чате по примеру context-compressor, если SDK и совместимость это позволяют. Предусмотреть отключение в настройках собственного плагина; проверить расход контекста. Детали и предложенные значения по умолчанию — в [ТЗ](requirements/chat-visualization.md).

## Принятые в планах допущения автора

- Имя проекта — LM Studio Companion; корень `G:\Projects\LMStudioCompanion`.
- Одна локальная панель управления, общение в LM Studio. Это не обещание встроенной вкладки.
- Память по умолчанию сохраняется явно; автоматический режим предлагает факты, пользователь может его включить. Существующая настройка старого плагина не изменяется при планировании.
- Профили подбираются измерением; контекст 16К/32К/64К — кандидаты для сравнения, не гарантированные пресеты. 128К+ не устанавливается автоматически.
- Никакой дополнительной классифицирующей LLM, Electron и голосового стека в первом выпуске.
- Копия веба помещена в `packages/web-tools`; действующий MCP не перенастраивается.
- Проект закрепляется за чатом. Переключение проекта в панели применяется только к новому чату; при неизвестном стабильном ID чата scoped auto-injection недоступна.
- Временная память ограничена текущим чатом и текущим запуском Companion; sessionId не сохраняется на диск. Закрытие только LM Studio не означает завершение host.

## Поправки к приложенному предложению Gemini

Решения завершения этапа 00: поставка с проверенным Node 24.22.2; установка версий отдельно от данных; отсутствие фиктивной MCP-регистрации локальной панели; индикация Companion в локальной панели до проверки собственного нативного канала. Обоснования и цена ограничений — в [итоговом отчёте](research/stage00-completion.md) и [исследовании индикации](research/chat-visualization.md).

1. Детерминированный конверт ошибок и существующий ID источника не доказывают, что факт в ответе соответствует источнику. Нужны отдельные проверки, а абсолютное отсутствие галлюцинаций не обещается.
2. Нельзя «подменить ответ инструмента системной блокировкой»: сообщение инструмента не становится system. Запрет в тексте — инструкция; жёсткий итог для недоступной страницы должен формировать владелец вывода.
3. Скриншот CAPTCHA показывает CAPTCHA, а не закрытое содержимое. Такой результат остаётся blocked.
4. Ограничение в 200 символов уже есть у текущего read_page как триггер браузера. Короткий корректный ответ не должен автоматически считаться ошибкой; порог — сигнал качества, а не доказательство.
5. Maximum context и максимальная скорость — разные цели. Учитывать свободную память, KV, embedding-модель, изображения и текущие другие процессы. Не перезагружать модель на каждый запрос.
6. Улучшения на базе persistent-memory и rag-v1 не означают бесконтрольную запись в их данные или автоматическую совместимость их внутренних TS-модулей.
