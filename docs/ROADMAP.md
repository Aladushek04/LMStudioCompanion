# Очередь реализации

Выполнен первый автономный срез этапа E: read-only советник, см. [01a](plans/01a-advisor-mvp.md). Автоматическое применение, бенчмарки и остальные этапы ещё запланированы. Нумерация модулей сохраняет номера пользователя; этапы выпуска имеют отдельный порядок.

В этапе A готовы задачи 1–2: контракты, read-only диагностика, выбор tools-only и локальная панель состояния. Панель запускается через Start-Companion.cmd; есть [инструкция](USER-GUIDE.md) и [проверки](research/panel-progress.md). Новый владелец генерации не включён; совместимость остаётся unknown. Установка/откат и поставка для чистой машины (задача 3) ещё не завершены. Этап A целиком не закрыт.

| Этап | Что получает пользователь | План | Условие завершения |
|---|---|---|---|
| A. Проверка интеграции и общая основа | Диагностика одним экраном; доказанный способ подключения | 00 | Матрица capabilities, один владелец генерации, доступная локальная панель и тест отмены |
| B. Надёжный веб | Обычные запросы без `read_page`, понятные сбои, источники | 06 | Контрольные сценарии веба проходят с текущей Gemma; ограничения документированы |
| C. Понятная память | Видимые записи, исправление, сохранение и забывание | 03 | Проверен перенос тестовой БД, один писатель, отсутствие записи после ошибки, изоляция проектов |
| D. Документы | Понятные прикрепления, источники и режим «только по документам» | 04, задачи 1–2 | Работают текстовый PDF и TXT, пустой результат не маскируется ответом по памяти модели |
| E. Профили модели | Подбор параметров и применение сохранённого профиля | 01 | Dry-run, действительное применение после ответа, проверенный возврат |
| F. Thinking | Ручные режимы и затем «Авто» | 02 | Подтверждённое включение/выключение; инструменты и изображения не ломаются |
| G. Библиотеки папок и упаковка | Папка подключается один раз; один комплект установки | 04, задача 3; 00, задача 3 | Инвалидация изменённых файлов, удаление из поиска, установка/откат на чистом тестовом профиле |

Порядок B → C → D → E → F — предложение автора: сначала исправить ежедневные неудобства и получить наблюдаемость. Профили можно делать раньше D, если этап A выявит простой независимый путь. Автоматический Thinking не блокирует выпуск остальных функций.

## Контрольные точки

- **A1:** нет совместимого обработчика генерации — выпускать статусы и панель, а гарантию контроля ответа не включать; выбрать один режим интеграции по отчёту.
- **C1:** нет безопасного management API persistent-memory — совместимый fork с отдельным ID, а не редактор живого файла.
- **D1:** SDK не даёт устойчивую библиотеку FileHandle — первый выпуск только прикрепления; папки явно отмечены как следующий этап.
- **F1:** нет поддержанного способа переключать Thinking — оставить штатный переключатель LM Studio и объяснение; не выдавать текстовую инструкцию за аппаратное выключение.

## Общее определение готовности

Каждый этап: работающий пользовательский сценарий, проверка ошибок и отмены, короткий отчёт с версиями, проверка на текущей 12B и отдельный результат для 26B только после её реального запуска. Результат 12B не переносится автоматически на 26B. Не включать новую модель ради самого составления планов.

До исполнения планов нужны только выбранный очередной этап и поручение на разработку. Сами планы и исходная копия уже подготовлены; они не устанавливают новые функции.
