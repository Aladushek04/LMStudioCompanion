# C4: изменения памяти из чата — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Выполняется только C4, без перехода к C5.

**Goal:** Подготовить из прямого сообщения пользователя предложение сохранить, исправить или забыть запись; применить только подтверждённый текст с защитой ручных правок.

**Architecture:** Детерминированный capture без LLM. Препроцессор передаёт исходное сообщение единственному владельцу C1 через C3-канал. Канал может подготовить предложение, но не подтвердить его. Панель показывает предложение и управляет применением через защищённое API.

**Tech Stack:** TypeScript/Zod/Vitest, существующий React/Edge, собственный нативный препроцессор.

**Spec:** [C4](03-memory-stages.md), [план 03](03-memory.md), [DESIGN](../DESIGN.md).

## Решения реализации

- Подтверждение в существующей панели, а не через experimental диалог SDK и не через второй генератор. Все изменения из чата, в том числе явное «запомни», сначала предложения. Цена: дополнительное действие в панели; нативное подтверждение остаётся будущим улучшением.
- Три режима чата: выключено (по умолчанию), явные команды, команды и предложения. Разбор без LLM и фоновых генераций; ограниченный набор прямых русских формулировок. Это не произвольное смысловое извлечение.
- Только global при неизвестном chatScopeId. Панельное подтверждение проекта не выводится из текущего выбора проекта.
- «Не сохраняй/не запоминай» сильнее извлечения. Цитаты, код, сайты, ролевая игра и вымышленные примеры не становятся личными фактами. Явные кавычки разрешены только как параметры команды исправления/забывания.
- Очередь RAM: максимум 32 предложения, срок 1 час, очищается при перезапуске. Нет журнала исходных сообщений. Подтверждённые записи сохраняются C1 и переживают restart.
- Правка/удаление привязаны к ID и revision, новый факт — к revision хранилища. Обновление устаревшего предложения отдельно показывает актуальную версию и снова требует подтверждения. Удалённая запись не восстанавливается поздним предложением.
- Статус в чате отражает только реальное состояние: «предложение подготовлено», не «сохранено». Ответ модели не является доказательством записи. Старые ответы/summaries не переписываются.

## Задачи

- [x] Capture: тесты RED→GREEN для прямых команд, запрета, цитат/веба/примеров, opt-in предложений; `packages/memory/src/capture.ts`, `tests/memory/capture.test.ts`.
- [x] Очередь и подтверждение: `proposals.ts`, атомарная проверка revision C1 при создании; тесты create/edit/delete/отказ/опоздание/restart/ошибка диска/повтор/лимиты. Отдельный коммит.
- [x] Канал и препроцессор: ограниченный запрос capture, настройка чата и честные статусы; тесты отказа/отмены/отсутствия LLM и сохранения веб-поведения.
- [x] API и панель: список, редактирование текста, сохранение/исправление/отказ, явное подтверждение удаления/перезаписи, обновление после конфликта. Проверки API и настоящим браузером. Отдельный коммит.
- [x] Полный Vitest/tsc/build, одно независимое финальное ревью, приёмка на синтетическом чате с текущей 12B и компрессором; новая поставка и отчёт. Не читать личную память, не загружать 26B. Коммит/push и остановка.

## Фокус проверки

Команда в цитате; «не сохраняй» после положительной команды; два окна подтверждения; ручная правка после подготовки предложения; delete до позднего принятия; ошибка записи и повтор; отмена или потеря связи не объявляются сохранением; очередь и повторные сообщения ограничены.
