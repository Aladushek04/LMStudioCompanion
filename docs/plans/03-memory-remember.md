# Сохранение по обычной просьбе — план исправления

> **Черновик заменён. Не исполнять как действующий план.** После уточнения пользователя нужен общий механизм через LLM в собственном цикле ответа, а не разбор частных формулировок. Актуальная очередь — [Companion Core CORE-0–CORE-7](07-companion-core-stages.md), сохранение — CORE-2, карточки/версии — CORE-3. Разработка документов приостановлена до приёмки всего Core. Ниже сохранена первоначальная идея для истории, не статус реализации.

**Goal:** Явное «запомни» сохраняет указанный текст или доступную полную карточку с проверенным результатом; карточки отделены от личных фактов.

**Architecture:** Существующий препроцессор разрешает ссылку на ограниченный фрагмент доступной истории без LLM-генерации. Единственный host сохраняет личные факты через MemoryStore, карточки — через отдельный владелец `characters/`, с атомарной записью и версиями. Карточка подключается явно по ID в настройках данного чата, а не по неподтверждённому chatId. Текущий capture предложений сохраняется для автоматических предложений и режима подтверждения.

**Tech Stack:** TypeScript/Zod, текущий SDK 1.5.0, React и именованный канал C3. Новые зависимости не нужны.

**Spec:** [Требования](../requirements/memory-next.md), уточнение пользователя 1 ноября: явную просьбу сохранять сразу. Это поручение переносит исправление запоминания перед D4. Тесты реализованных функций параллельно готовит другой ИИ: его файлы не менять и не включать в свои коммиты.

## Решения

- Короткое «Запомни, что …» / «Запомни …» работает без обязательного двоеточия. Для «это» сохраняется только однозначный доступный текст, не реконструированный моделью.
- Карточка: максимум 64000 символов, до 10 версий, общий файл до 8 MiB. Не обрезать молча. При обновлении требуется текущая revision; одинаковый повтор не создаёт версию, ручная правка защищена.
- Карточки не участвуют в global recall. Выбранная карточка подставляется как данные с измерением полного запроса; переполнение даёт явный отказ.
- При отсутствии текста, ошибке записи или неоднозначности препроцессор прекращает этот ход с точной причиной, чтобы модель не могла объявить сохранение. Новый генератор не включается. Сохранение не выполняется в ответ на команду из веба/карточки/цитаты.
- Существующие команды исправления/забывания фактов сохраняют подтверждение панели. Режим «сначала подтверждать» для фактов тоже доступен; автоматические предложения никогда не записываются сразу.
- Нельзя автоматически назначить новому чату последнюю карточку: пользователь выбирает её ID в per-chat настройках. Создание возвращает ID и доступно в отдельном разделе карточек панели.

## Шаги

- [ ] Разбор прямых просьб и разрешение контекста; отдельная проверка на вымышленных данных вне файлов другого ИИ.
- [ ] Хранение карточек/версий, явное сохранение фактов, IPC и management API; проверить restart, повтор, конфликт, отмену, ошибку диска, один писатель.
- [ ] Препроцессор, настройки и измеренная подстановка выбранной карточки; проверить отсутствие новых генераторов и fallback в global.
- [ ] Панель карточек, актуальные инструкции, сборка плагина для локальной проверки; проверить браузером и доступными тестами.
- [ ] Коммиты только собственных файлов, отчёт с точными границами. Публичный release не выпускать.
