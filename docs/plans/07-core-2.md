# CORE-2 — настоящее запоминание по просьбе

> Исполнение: superpowers:executing-plans, в основном агенте, без субагентов. Поручение пользователя и утверждённые требования CORE-2 задают объём; новый выбор продукта не требуется.

**Goal:** обычная явная просьба сохраняет общую заметку через текущую LLM и единственного владельца памяти; подтверждение следует только за проверенной записью.

**Architecture:** текущая LLM последовательно разбирает намерение в ограниченном структурированном запросе, затем вызывает инструмент сохранения. Разбор читает последнее сообщение отдельно от помеченной истории, без веб-инструментов и без записи. Host выдаёт краткоживущее разрешение на конкретное содержание/ревизию. Store атомарно фиксирует запись и квитанцию операции в существующем снимке. Итог хода сохранения выводится кодом из квитанции; свободный ответ модели этого хода не публикуется. Если намерение пропущено, обычный ответ буферизуется и проходит отдельную смысловую проверку на неподтверждённое заявление о сохранении.

**Tech Stack:** TypeScript, Zod 3.25.76, SDK 1.5.0, Vitest, Windows, Node 24.22.2.

**Spec:** ../requirements/companion-core.md, CORE-2 в 07-companion-core-stages.md.

## Ограничения

- Только общие факты/заметки. Карточки, исправление и забывание через LLM — CORE-3. Документы и советник не развиваются.
- Существующая очередь предложений сохраняется; автоматического немедленного сохранения нет.
- Чужие dirty/untracked файлы не изменять и не добавлять в коммиты. Работа в указанной ветке от 5016b64; новый worktree не нужен.
- Семантика естественного языка зависит от текущей LLM. При неполном/невалидном разборе, неоднозначной ссылке, недоступном содержании — отказ/уточнение, без записи. Приведённая дословная часть текущей просьбы проверяется кодом; история/цитаты не являются разрешением.
- Нативную проверку выполняет пользователь в пустом тестовом чате. Автотесты используют вымышленные данные и временные каталоги. Рабочие чаты/память не читаются.

## Проверить отдельно при ревью

1. Квитанция и запись фиксируются одним rename; потеря ответа не вызывает повторную запись.
2. Повтор после ручной правки/удаления не восстанавливает запись и не сообщает об актуальном сохранении.
3. Отмена до rename и обрыв после rename различаются; неизвестный результат нельзя назвать отказом или успехом.
4. Источник/цитата/отрицание/карточка не создают право на личный факт; переполнение не обрезает исходник молча.
5. Обычный цикл, сторонние инструменты, старые снимки, экспорт и предложения остаются совместимы.

### Task 1: атомарная операция владельца памяти

**Files:** packages/memory/src/operations.ts (новый контракт), types.ts, store.ts; tests/memory/core-operations.test.ts.

**Interfaces:** `saveExplicit(request, signal?)`, `getOperation(operationId)`; запрос save с operationId, expectedStoreRevision, content, targetId/targetRevision=null. Квитанция содержит состояние, ID/редакцию/сохранённый текст. Снимок получает необязательный журнал квитанций; старый формат читается без изменения checksum.

### Task 2: канал и право на конкретную запись

**Files:** channel-protocol.ts, packages/host/src/memory-channel.ts; tests/memory/core-channel.test.ts.

**Interfaces:** begin-save → grant/baseRevision; save → квитанция; operation → проверка результата по operationId. Авторизованный named pipe переиспользует владельца панели. Grant привязан к тексту/ID/ревизии, имеет срок, не является командой из модели.

- [x] GREEN: проверка grant, отмена по закрытию сокета до фиксации, проверка уже выполненной операции прежде grant.
