# Companion Core — подэтапы CORE-0–CORE-7

> Выполнять последовательно, по одному заказанному подэтапу за заход. Использовать writing-plans для детального плана подэтапа и executing-plans для исполнения в основном агенте. Субагенты по умолчанию не нужны. Переходить к следующему подэтапу только по отдельному поручению.

**Goal:** Полноценный собственный цикл ответа со сжатием, памятью, вебом, сохранением сторонних инструментов и понятным управлением.

**Architecture:** `packages/conversation-engine` владеет циклом текущей LLM; собственные host/memory/web-tools обслуживают данные и действия. Контракты бюджета, источников и результата операции общие. Новое ядро сначала работает в тестовом чате, затем явно заменяет прежнего владельца ответа. Панель документов D0–D3 сохраняется, развитие D приостановлено.

**Tech Stack:** Существующие TypeScript/Zod, LM Studio SDK 1.5.0 как исходная проверенная база, React, Vitest/Playwright, Windows и комплектный Node 24.22.2. Изменения SDK/runtime — только после проверки, не подразумеваются.

**Spec:** [Требования к Core](../requirements/companion-core.md), [исследование основы](../research/context-compressor-foundation.md), [память](../requirements/memory-next.md), [лицензии](../../THIRD-PARTY-NOTICES.md).

Это рамочная разбивка. Имена новых внутренних типов и путей ниже — проектируемые контракты Companion, не обещание наличия одноимённых методов в LM Studio. Подробные сигнатуры и тесты фиксируются в плане конкретного CORE-N после предыдущей приёмки.

## Общие правила

- Один подэтап = полезный результат, проверки, отчёт с ограничениями и отдельный коммит. Не делать весь Core одним заходом.
- Личные чаты, записи и рабочий кэш не используются для разработки. Нативные проверки — в пустом чате на вымышленных данных, с уже загруженной моделью; 26B не загружать.
- Реализацию и тесты не путать: второй ИИ готовит P0-проверки существующих A–C/D0–D3. Не изменять и не включать в свои коммиты его незавершённые файлы. Новые проверки Core размещать отдельно, прежде всего в `packages/conversation-engine/tests/companion/`.
- Использовать комплектный Node для согласованной приёмки. В CORE-1 отдельно привести заявленный диапазон поддержки в соответствие с проверенными версиями; не объявлять Node 25 неподдерживаемым только из-за двух падений тестов.
- Одна операция хранения имеет устойчивый ID и однозначный результат; успех, повтор, конфликт, отмена и неизвестный из-за потери связи результат различаются.
- Публичный release не выпускается после CORE-N. До завершения полного Core — коммиты и локальные кандидаты. Публикация после приёмки полного этапа — отдельное решение по [RELEASING](../RELEASING.md), без автоматического изменения нынешнего правила выпусков A–G.
- Разработка документов D4/D5, советника и Thinking не возобновляется автоматически.

## CORE-1. Собственный работающий цикл ответа

**Результат:** в отдельном тестовом чате ответ ведёт именно Companion Core; текст, инструменты, остановка и ошибки работают без второго владельца ответа.

**Основные файлы:** `packages/conversation-engine/src/index.ts`, `handler.ts`, новые небольшие модули в `src/companion/`, `manifest.json`, `scripts/build-conversation-engine.mjs`; необходимые изменения диагностики/описания интеграции host — по отдельному детальному плану.

- [ ] Проверить установленную LM Studio 0.4.28, жизненный цикл обработчика, токенизатор, выдачу инструментов и подтверждения tool calls. Использовать публичные возможности SDK; отсутствие возможности записать в отчёт.
- [ ] Разделить точки расширения для памяти, веба и бюджета, сохранив проверенное сжатие. Не переписывать весь upstream handler без необходимости.
- [ ] Сделать русский понятный статус владельца ответа и нативных ошибок. Ошибка сессии инструментов не должна молча превращать запрос требуемого действия в ответ без выполнения.
- [ ] Подготовить и проверить явное включение только в пустом чате и возврат к прежнему обработчику. Не менять личные чаты и установленные сторонние исходники.
- [ ] Зафиксировать проверенный runtime и правила совместимости, не смешивая обычный ответ с автоприменением профилей или Thinking.

**Приёмка:** простой ответ; текущий сторонний инструмент и продолжение после него; изображение/вложение не теряется; остановка; ошибка инструмента и следующий успешный ход; возврат к прежней связке. Статическое наличие метода SDK не заменяет live-проверку.

**Следующему подэтапу передаёт:** проверенный один цикл, контекст текущего хода, отмену, подключение собственных инструментов и управляемое завершение ответа. После отчёта и коммита остановиться.

## CORE-2. Настоящее запоминание по просьбе

**Результат:** «Запомни, что…» и ссылка на однозначно доступное содержание беседы приводят к реальной записи факта/заметки, видимой в панели и после restart.

**Основные файлы:** новые `packages/conversation-engine/src/companion/memory-tools.ts` и `memory-turn.ts`; адаптация `packages/host/src/memory-channel.ts`, протокола `packages/memory/src/channel-protocol.ts` и владельца `store.ts`. Названия уточняются детальным планом.

- [ ] Определить и проверить схемами запрос изменения и квитанцию: operationId, действие, целевой ID/revision, результат и сохранённая редакция. Обеспечить идемпотентность повторной доставки.
- [ ] Дать текущей LLM инструмент сохранения и разрешения смысла просьбы в контексте. Не заменять его новым списком обязательных русских шаблонов и двоеточий.
- [ ] Подтверждать право на запись текущей прямой просьбой пользователя; текст из веба, карточки, цитаты и старого summary такого права не даёт. Неоднозначный выбор уточнять до записи.
- [ ] Явная просьба сохраняет сразу через владельца хранения. Автоматическое извлечение оставляет предложение; старый интерфейс предложений сохраняется.
- [ ] Формировать итог операции из проверенного результата host. Если модель не вызвала сохранение, операция отказана или результат неизвестен — не выпускать положительное подтверждение «запомнил».

**Приёмка:** разные обычные формулировки; ссылка на предыдущий доступный текст; реальная запись в панели и после restart; отсутствующий tool call; неуспех диска/сервиса; повтор; отрицание и команды из источника; отмена до фиксации и потеря связи после фиксации. Известный XFAIL для этих сценариев должен быть заменён проверяемым результатом, а не удалён из отчёта.

**Граница:** только разрешённая общая память фактов/заметок. Карточку нельзя временно сохранять как личный факт ради прохождения теста — она относится к CORE-3. После отчёта и коммита остановиться.

## CORE-3. Управляемая память, карточки и версии

**Результат:** можно исправлять/забывать сохранённое, отдельно хранить карточки и подключать актуальную версию только к выбранным чатам.

**Основные файлы:** `packages/memory/src/`, собственные memory-tools Core, `packages/host/src/routes/memory.ts`, `packages/control-panel/src/features/memory/`. Ранее созданные незавершённые черновики сначала проверить и переработать; их наличие не означает реализацию.

- [ ] Подключить чтение, исправление и забывание с точным ID/revision и сохранением действующих подтверждений опасных действий. Уточнение выбора не подменять догадкой модели.
- [ ] Отделить карточки и их версии от общей памяти личных фактов; поддержать полный текст, явные лимиты, сравнение/обновление и отображение актуальной редакции.
- [ ] Проверить стабильную привязку чата. Если ID недоступен — явное подключение конкретной карточки в per-chat настройке; без автоматической подстановки последней карточки в новые чаты.
- [ ] Подбирать сохранённое к вопросу, учитывать ручной приоритет и показывать, что реально передано. Полное хранение материала отделить от его включения в контекст.
- [ ] Сохранить работу CRUD, экспорта/переноса и одного писателя; интерфейс карточек и результат записи должны использовать того же владельца.

**Приёмка:** новая карточка → исправленная версия → restart; два чата с разным явным выбором; ручная правка между подготовкой и записью; забывание против позднего результата; отсутствие карточек среди личных фактов; лимит длины без скрытого обрезания; конфликт двух окон.

**Граница:** отсутствие доказанного chat ID не разрешает включить project/session автоматически. После отчёта и коммита остановиться.

## CORE-4. Согласованное сжатие и бюджет контекста

**Результат:** длинный диалог продолжает работать, а сжатие не уничтожает результаты операций и не возвращает старые версии памяти.

**Основные файлы:** `packages/conversation-engine/src/handler.ts`, `budget.ts`, `viewPlan.ts`, `summarizer.ts`, `toolWrap.ts`, `usage.ts`, модули `src/companion/`; общие контракты бюджета по необходимости.

- [ ] Согласовать истории, текущие материалы, закреплённые записи, выбранные карточки, схемы инструментов и резерв ответа в одном бюджете. Различать измеренное и оценённое; ошибки измерения не маскировать точными числами.
- [ ] Сохранить `/compress`, `/usage`, автоматическое и промежуточное сжатие, ограничение роста summary и отмену.
- [ ] Защитить квитанции памяти, ID/revision, ошибки, источники и незавершённые действия от общего усечения результатов инструментов.
- [ ] Не считать summary подтверждённым хранилищем и не заменять им полный текст активной карточки. Новые редакции и забывание имеют приоритет над старым резюме.
- [ ] Показать фактический результат сжатия и недостающий бюджет. Если обязательный материал не помещается — сообщить границы, а не продолжать с молчаливой потерей.

**Приёмка:** сохранение/правка/забывание до и после сжатия; квитанция в длинном tool-result; длинный цикл инструментов; изменённая история; restart кэша; переполнение от схем инструментов/карточки; отмена с повтором. Никакой загрузки другой модели для расширения окна.

После отчёта и коммита остановиться.

## CORE-5. Собственный веб в общем цикле

**Результат:** Core сам читает ссылки, ищет и рассматривает веб-изображения без обязательного стороннего веб-плагина.

**Основные файлы:** адаптеры `packages/conversation-engine/src/companion/`, переиспользуемые `packages/lmstudio-plugin/src/web/`, `packages/web-tools/` и реестр источников `packages/core/src/sources/`.

- [ ] Подключить существующую веб-обработку к циклу Core без второго параллельного чтения прежним препроцессором.
- [ ] Сохранить режимы «выключен / авто / исследование», источники, контроль бюджета, ошибки, отмену и ограничения доступа.
- [ ] Связать статус «прочитано» с фактическим получением содержания; 403/CAPTCHA/таймаут не маскировать пересказом по адресу или знаниям модели.
- [ ] Оставить сторонние инструменты доступными по выбору; режим выключения относится к встроенному вебу и не притворяется запретом отдельного MCP.
- [ ] Сохранить порядок: явные материалы → закреплённые предпочтения → дополнительный поиск и обычная память.

**Приёмка:** «прочитай ссылку», поиск с чтением, изображение, 403, пустая страница, недоступный поиск, отмена и последующий обычный вопрос; сочетание веба, памяти и сжатия без повторных действий.

После отчёта и коммита остановиться.

## CORE-6. Единое управление и локальная поставка

**Результат:** пользователь видит, что включено, какие действия выполнены, и может установить/обновить/отключить собственный Core с понятным возвратом.

**Основные файлы:** настройки/manifest Core, `packages/control-panel/src/`, диагностика/конфигурация host, `scripts/build-conversation-engine.mjs`, упаковка/установочные скрипты и инструкция.

- [ ] Объединить русские настройки памяти, карточек, веба, сжатия и отображения состояния. Завершение каждого пользовательского действия имеет видимый результат; технические подробности раскрываются отдельно.
- [ ] Отображать именно активный обработчик и подтверждённые возможности, а не готовность только по наличию пакета на диске.
- [ ] Подготовить один локальный комплект собственных компонентов с лицензиями. Кэши/настройки/данные сохраняются или переносятся явно через владельца с резервной копией.
- [ ] Сделать конкретный сценарий переключения и возврата; чужие плагины не удалять и не перезаписывать. Не обещать работу двух владельцев ответа одновременно.
- [ ] Не включать в поставку личные записи, токены и кэш. Новый Core не должен читать рабочий кэш оригинала автоматически.

**Приёмка:** чистый тестовый профиль, установка/повторное обновление/возврат, сохранность тестовой памяти, неверная настройка, отсутствие LM Studio, узкий экран/масштаб/клавиатура. Публичный Hub не используется.

После отчёта и коммита остановиться.

## CORE-7. Приёмка полного Companion Core

**Результат:** подтверждён весь пользовательский путь, собран проверенный локальный комплект, нет обязательной зависимости от чужих плагинов для встроенных сжатия/памяти/веба.

- [ ] На комплектном Node прогнать подходящие общие проверки A–C/D0–D3 и отдельный набор Core. Отчёт второго ИИ использовать как независимые результаты с указанием фактической версии/коммита; не выдавать старый прогон за тест нового кода.
- [ ] В пустом нативном чате на текущей модели пройти весь путь: обычный ответ → память → карточка/версия → веб/источник → сжатие → recall → правка/забывание → restart. Сторонние встроенные аналоги отключены именно в этом тестовом чате.
- [ ] Отдельно проверить отказ инструмента, ошибку записи, неоднозначность, отмену, повторную доставку и отсутствие ложных сообщений об успехе.
- [ ] Проверить дополнительные инструменты и явный возврат к прежней связке; зафиксировать реальные ограничения.
- [ ] Сверить готовый комплект, документацию и отчёт, актуализировать статус. Решение о публичном выпуске принимается после полной приёмки, не после промежуточного CORE-N.

**Условие завершения:** выполнено определение готовности из [требований](../requirements/companion-core.md); нет незакрытых критических проблем с потерей данных, повторной записью, чужой областью или ложным успехом операции памяти. Необязательные ограничения перечислены явно.

После приёмки Core остановиться. Документы D4/D5 возобновляются отдельным поручением, с уже готовой границей бюджета/источников и одним владельцем ответа.
