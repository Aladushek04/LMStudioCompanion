# Публичные выпуски Companion

Решение пользователя от 2026-10-30: публичный **GitHub Release выпускается после завершения и приёмки полного этапа A–G**, а не каждого подэтапа. Внутри этапа нужны своевременные коммиты; локальные ZIP служат проверке и не становятся автоматически публичными релизами.

Первый публичный выпуск — **v0.1.5**, объединяющий принятые результаты A–C. Следующий плановый публичный выпуск — после полного D. Не публиковать задним числом 0.1.0–0.1.4 как самостоятельные завершённые этапы. GitHub Releases и LM Studio Hub — разные места; публикация в Hub сюда не входит.

**v0.1.5 опубликован 2026-10-30:** [страница релиза](https://github.com/Aladushek04/LMStudioCompanion/releases/tag/v0.1.5), [проверка публичного скачивания, хешей и тега](../reference/github-release-v0.1.5.json). ZIP и .sha256 скачаны без авторизации и совпали с проверенными локальными файлами; релиз отмечен Latest.

## Перед публикацией

1. Зафиксировать фактическую приёмку этапа, известные ограничения, версии и результаты проверок. Подэтап с незакрытым обязательным критерием не объявлять завершённым этапом.
2. Взять согласованный commit основной ветки. Версия package.json, имя архива, release-manifest и tag v<версия> должны совпадать. Тег связывает выпуск с исходниками; опубликованные файлы не заменять другой сборкой под тем же именем.
3. Собрать Windows x64 комплект и SHA-256. Проверить хеши каждого файла из release-manifest, отсутствие пользовательских данных и наличие лицензий. После изменения сборки повторить уместные установочные проверки; не повторять тяжёлые модельные тесты без нового риска.
4. Подготовить русский текст релиза: что работает, как запустить, какие части устанавливаются отдельно и что ещё не реализовано. Не называть ZIP исходников готовым приложением.
5. Создать draft Release, загрузить проверенный ZIP и .sha256, сверить размер и digest загрузок. Только после этого опубликовать выпуск и отметить его Latest.
6. Проверить публичную страницу, tag/commit и скачивание файлов без авторизации; сверить SHA-256 скачанного архива. Обновить ссылки README и сохранить результат проверки. При неудаче не выдавать публикацию за успешную.

Каталог releases/ остаётся в .gitignore. Архивы распространяются как вложения GitHub Release, исходники и отчёты — через Git. Предыдущие локальные сборки не удаляются этой процедурой.

## Обновление приложения

В 0.1.5 используется ручной Install-Companion.cmd из нового архива после остановки панели. Версии, данные и откат уже разделены установщиком. [Требования к будущей кнопке обновления](requirements/in-app-updates.md) относятся к G; автоматическое обновление пока не реализовано.

API публикации и загрузки: [GitHub Releases](https://docs.github.com/en/rest/releases/releases), [Release assets](https://docs.github.com/en/rest/releases/assets). Авторизация используется только для публикации; публичному клиенту обновления токен владельца не нужен.
